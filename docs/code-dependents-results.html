A change to a function: every dependent, in the context and the answer

You asked for tests that, if they pass, mean that when a request changes something in a function, say its arguments, every dependent (callers, callees, and on through routes to the screens) reaches the graph context and the final answer. Here is the suite that holds the code to that, what it found, and how the models did with it.

The context: yes, and checked without a hand-written list. For each of the shop's 35 functions, tests, constants and routes, the test works out every dependent and dependency from the index's own links, then requires all of them in the code block, with the line of each direct use. 35 of 35 pass: 166 dependents and 59 call-site lines. The final answer: as complete as searching, and faster. What this does not cover

  • The oracle checks the answer against the index's own links. It cannot notice a link the indexer never makes. That is what the tests on the index and the hand-written cases are for, and the list below is what the indexer does not make yet.
  • A request field read in another function: create_refund passes the body to validate, which reads order_id, and that read is not counted as a read of the request.
  • Calls through getattr, registries filled at run time, or attributes set elsewhere; from x import *; TypeScript re-exports; methods inside classes.
  • The context is complete. Whether the answer uses all of it is up to the model, and the misses above show it sometimes does not.
  • The shop is small and was written alongside the indexer.
