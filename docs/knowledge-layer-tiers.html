The knowledge layer as three tiers

Same map, three shapes:OnionPyramidThree tiers

The same three layers as the onion, drawn as a classic three-tier architecture. The layers have equal widths, with the data tier at the bottom and the people who decide at the top. This view is about boundaries: what crosses from one tier to the next, and who plugs in where.

One boundary is built: the one between layers 1 and 2. It is REST at /v1 and MCP at /mcp, both over the same service, plus an event feed with signed webhooks. Edits to projects, plans and deliverables are change requests that a person approves. In the hosted service, every layer-2 client reaches the graph through this boundary.

The boundary between layers 2 and 3 is designed, not built. The daily report would be saved graph queries. Commitments and decisions would arrive as change requests, so the same approval rule holds at the top. Links saying which bet each piece of work serves would join the two tiers.

Who plugs in where

  • An input handler works only at the bottom boundary. It sends files and never edits the graph directly.
  • A task app sits in layer 2. It reads approved projects, proposes edits, and is where people approve them.
  • An execution platform sits in layer 2 too. It leases tasks to its machines and injects each run's credentials, including this service's run token. Its agents work through the run protocol over REST or MCP.
  • The CEO's report would sit in layer 3, reading through the same boundary with saved queries.

Equal widths make one point the other shapes don't: the same two write rules hold in every tier. A file becomes current once code has checked its quotes and a trial build, and a file that conflicts is held for a person. An edit to a project, a plan or a deliverable is only ever proposed, and one person's approval applies it. Layer 3 would follow both rules.

Which shape, when

All three pages draw the same three layers with the same status markers. The shape decides which relationship the reader sees first. The pyramid draws the graph memory inside layer 1 and groups layer 3's items so the point stays small. The onion and the tiers draw the core on its own and list every item.

Each shape hides something. The onion makes the outer layer look biggest, when it holds the fewest items. The pyramid makes the top look remote from the base, although the OpenSpec loop and the decision walks cut straight through. The tiers make the layers look independent, but they share one graph, so a question in tier 3 is answered by a walk that reaches tier 1.
