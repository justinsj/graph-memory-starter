The model answers from memory now

Round two finished the list from round one: quotes on the facts' own lines, no folder name to chase, a standing rule for CLAUDE.md, labelled RAG passages when the graph has no match, and a warm embedding model. Retested live against round one's code on the same questions, plus one the graph cannot place.

Fixed in the setup a user actually has, once the CLAUDE.md rule is in. In the folder holding the graph's own documents, with every prompt opening “Our company docs are in this folder.”, Sonnet 5 searched in 2 of 11 runs. Round one's code searched in 9 of 11. Tool calls fell from 50 to 6, average time from 12.7 s to 7.8 s, and cost per question by 43%. The runs that still searched were the question whose documents name nobody for the role, and the question the graph cannot place.

The code changes alone were not enough there. Without the rule, the same setup still searched in 9 of 11 runs. The searches were smaller (50 tool calls down to 28): Sonnet opened the one cited file to confirm instead of reading the folder.

The rule holds in a folder of other documents too. Among 12 documents that are not the graph's sources, Sonnet searched in 1 of 10 runs without a hint (round one 2) and in 1 of 10 with “Our company docs are in this folder.” (round one 10). The code changes alone left those at 2 and 8. The one question that still searched everywhere is June 2025, where the documents name no Director.

91 of 91 answers were correct. The injection is smaller: 2,521 → 1,990 characters for the refund question, and the benchmark measured 644 input tokens on Haiku 4.5 (was 785) and 836 on Sonnet 5 (was 1,029).

A finding about the test harness

The live runs use --setting-sources local to keep your own settings out. That also stops Claude Code loading CLAUDE.md. A probe with a codeword in CLAUDE.md answered “NONE” under local and the codeword under local,project. So the Round two columns measure the code without the rule, and the + CLAUDE.md sets add project to load it. bench/live_eval.py writes no CLAUDE.md, so its numbers are without the rule too.

Tests

88 tests, all passing (python -m unittest discover tests). New this round: tests/test_fallback.py (the boss question gets labelled passages within budget; a question the graph answers gets none; without an index the loud line stands alone) and tests/test_embedder.py (nothing when it is not running; no index, no start; warm vectors equal local ones; a wrong key gets nothing). tests/test_excerpts.py now checks the provenance line names no folder, the model's lead carries no timing, the quote replaces the paraphrase on its line, and the changed and missing markers.

Still open

  • Paste the rule. The biggest effect in this retest comes from claude-md-snippet.md, and it only works once it is in CLAUDE.md. The README says so. The hook cannot do it for you.
  • Raise MAX_EXCERPTS from 8 to 12 (suggested, not made). With quotes inline, the 2,000-character budget is the real limit. On four of the ten questions the cap stopped the quoting first, and 2–4 claims went out paraphrased, including “Day one covers accounts and access” for onboarding. At 12 they are quoted, for 54–146 more characters. Untested live, and with the rule in place those questions did not search anyway.
  • The documents name no Director. That is a gap in the documents, not in the graph, and the unknown claim states it. Fill it in the documents and the last search goes.
  • One run per question. Differences of a few seconds are within noise. The counts of runs that searched and of tool calls are the firmer evidence.
