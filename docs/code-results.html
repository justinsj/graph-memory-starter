Code in the graph: eleven questions, tested

The graph can now hold a codebase beside the documents: functions, constants, routes, the branches a request body picks, and buttons, with what reaches what. It is indexed with no model, and names match in any naming style. Eleven test cases hold it to the four kinds of reference you asked for and seven that a claims lookup cannot answer.

All eleven cases pass as unit tests (22 tests on code, 199 in the suite, all passing): reference chains to a variable, explicit routes, routes in a variable, routes picked by a value in the body, the impact of a change, dead code, two functions with one name, code against the refund policy, frontend against backend, one name in any style, and a document question that must stay free of code.

Live, told where the code is, over both models and two runs of each question (times without the service's waits): the model reading the code itself got 42 of 44 right in 10.6 s on average with 206 tool calls; through the graph, 44 of 44 in 5.6 s with 2, 1.9 times faster.

Asked plainly (one run each): searching 19 of 22 in 10.4 s; the graph 22 of 22 in 5.3 s. Recall itself took 6–15 ms per question.

PartFilesWhat it does
Tokenizersrc/tokens.pySplits names and questions at the same seams: snake_case, SCREAMING_SNAKE, camelCase, PascalCase, kebab-case, dotted paths; a run of capitals is one word, digits stay with their letters, any alphabet. Recall and the build both use it, so prose is split as before.
Indexercodegraph/index.pyReads Python with ast and TypeScript/JavaScript with a small scanner; no model. Finds functions, components, constants, routes, the branches a body value picks, and buttons; resolves calls through imports and URLs through constants and template strings; matches client routes to server routes across languages. Writes extraction-format nodes, claims (each quoting its line), links and aliases.
Buildsrc/build_graph.py --code, src/schema.sqlLoads the code beside the documents and checks every quoted line against its file; code_symbols keeps each symbol's file, line and value.
Answerssrc/recall.pyTwo words in a row name code (“approval threshold” finds APPROVAL_THRESHOLD_GBP); a code name wins over the words inside it. A code: block traces what a named symbol leads to and what leads to it, eight links deep, with constants' values, and says when nothing reaches it. Changed files are marked, as documents are.
Cases and evalscodegraph/cases/, tests/test_code.py, bench/code_eval.pyA sample shop (Python API, TypeScript frontend), eleven questions with what the answer must and must not say, 22 unit tests, and a live eval of search against the graph.

What it does not read yet

  • Python methods inside classes (they count as part of the function around them), and nested functions.
  • Routes other than Flask-style decorators; branches other than if/elif on a body value (match and lookup tables such as ACTIONS[payload["action"]] are not read yet).
  • HTTP clients other than fetch (axios and the like), default imports, and JSX text with an apostrophe in it.
  • One codebase at a time. The sample is small; a large repository has not been measured.
  • The cases were written alongside the indexer, so they test what it was built to do. Questions about a codebase nobody here has seen would give a fairer number.
