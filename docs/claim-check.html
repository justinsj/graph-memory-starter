graph-memory-starter · README claim, measured

2 ms vs 20 s

Measured on 22–23 September 2026 with the repo's own code and 12 live claude -p runs. The 2 ms is real, but it is the name matching and SQL inside a 130–154 ms hook step, inside a 4–6 s answer. The search time is almost all model turns: Grep, Read and Glob ran for 0.10–0.14 s of each search run.

This page measured the code at commit 496a6e9, before the changes in improvement-proposals.html were applied. Current numbers: bench/recall-report.md and bench/live-report.md.

Retrieval: 2 ms per query. Holds at this size

recall() printed 2–3 ms in every graph run. That covers the name matching and SQL only. The hook step around it took 130–154 ms in Claude Code, mostly starting Python. It also grows with the graph: 89 ms at 3,013 entities.

The ~400-token injection is fixed at any corpus size Partly

The refund question injects 1,608 characters, which cost 459 input tokens on Haiku 4.5 and 635 on Sonnet 5. The cap is 8 facts, so it doesn't grow, but it isn't fixed: 68 to 1,627 characters by question. In a bigger graph the cap can push the answer out.

search reads grow with it Not tested

Every run used the same 12 documents, so growth can't be seen here. Each search run read 3,503–3,736 characters of documents in 5–6 tool calls.

20 s of visible searching vs an answer that starts immediately after the 2 ms recall line Partly

Search took 10.3–15.9 s here, not 20 s. With the graph, the recall line appeared 0.9–1.1 s in and the first answer word 2.5–4.0 s later, which is one model turn with thinking. That only holds when the model trusts the facts: told the docs were in the folder, Sonnet 5 re-read them and took 13.0–15.3 s.

Where the seconds go

Each tool call costs model time on both sides: the model writes the request, then reads the result before its next move. Search runs made 5–6 calls over 3–4 model turns. Graph runs that trusted the injected facts made none and answered in one turn.

What the 2 ms covers

The recall line reads “memory: 8 facts recalled in 2 ms” because recall() times itself. Around that call, Claude Code starts a Python process for the hook: 75 ms run on its own, 130–154 ms inside Claude Code. Around the hook sits the model's turn, which is most of the answer.

So “an answer that starts immediately” means no tool round trips, not no wait. The first word still comes after one full model turn: 2.5–4.0 s after the recall line in these runs.

Fixed size, not fixed content

The hook collects every fact within 3 hops of a name in the question, sorts them by how close they sit, and sends the first 8. That caps the size. For the refund question it adds 459 input tokens on Haiku 4.5 and 635 on Sonnet 5, measured as the difference in the first request's input between the two conditions. That is more than the README's ~400, which comes from dividing characters by four. Other questions inject less:

At bigger sizes

I grew a copy of graph.db with made-up entities and asked the refund question again. How the graph grows matters:

  • Growth elsewhere (separate clusters): the walk stays small, but matching names checks every entity in the graph, one pattern at a time. That step is 87 of the 89 ms at 3,013 entities. The answer stays in.
  • Growth around the Ops Manager: every new policy is one hop from the question, so the walk and the sort handle all of them. It reaches 161 ms at 1,013 entities and 12.7 s at 10,013. That is past the hook's 10 s timeout, so Claude Code would stop the hook and inject nothing. The answer drops out from 113 entities on.

How it was measured

  • The question was “A customer wants an £800 refund in March. Who signs it off?”. Hint runs open with “Our company docs are in this folder.” Without the hint, Haiku 4.5 didn't search at all and asked for the docs.
  • Both conditions had the same 12 files from corpus-before/ and the same tools (Grep, Read, Glob), with user and project settings and MCP servers turned off. The graph condition added only the UserPromptSubmit hook, src/recall_hook.py.
  • Runs used claude -p with stream-json output, and each event was timestamped as it arrived. Setup: Claude Code 2.1.280, claude-sonnet-5 and claude-haiku-4-5-20251001, Windows 11, Python 3.12.7, SQLite 3.45.3.
  • These are headless runs. The README's 20 s came from interactive terminal runs, where its Sonnet made up to 13 tool calls; here the models made 5–6.
  • The graph-growth test adds made-up entities to a copy of graph.db. The repo's own graph and code are unchanged.
