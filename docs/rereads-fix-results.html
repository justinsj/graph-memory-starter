Stopping the model re-reading the docs

The injection now carries the documents' own words, checked against the files each time, with a line saying where the facts come from and to answer from them. Tested live on the same questions, in the same folder where Sonnet used to search.

Partly fixed. Without a hint in the prompt, Sonnet's searching halved: 4 of 10 runs searched before and 2 of 10 with the fix (17 tool calls down to 6); its average time fell from 9.6 s to 5.0 s and its cost per question by 32%. Haiku did not search before and does not now.

A prompt pointing at the documents still wins. Told “Our company docs are in this folder.”, Sonnet searched in 10 of 10 runs before and 10 of 10 with the fix.

Every answer was correct in every set (30 of 30 with the fix). The injection grew by about 321 input tokens per prompt on average.

What was built

Everything from the list in why-the-model-rereads.html except the optional standing instruction in CLAUDE.md. The values are the ones recommended from the measurements below them.

SettingValueWhat it does, and why this value
quoteper claimEach claim carries the shortest passage of its document that states it, word for word. The build refuses a quote its document does not contain (markdown and spacing aside).
MAX_QUOTE300 charsLongest quote the build accepts. Sentences in the documents run 59–71 characters at the median, 87–112 at the 90th percentile and 295 at most, so any one sentence fits.
EXCERPT_BUDGET2,000 charsSource quotes per prompt, most relevant claim first. Document text measured 2.81 characters per token on Sonnet 5, so at most about 710 tokens.
MAX_EXCERPTS8Quotes per prompt, like the 8 facts. A quote backing several claims is sent once.
freshness checkevery promptEach quote is checked against the file as it is now. A changed file is marked “changed since extraction, check it”, a missing one “no longer in the documents folder”, so the model is told instead of finding out.
provenance line1 lineUnder the header: how many documents, which folder, when extracted, each fact names its source, and “answer from these facts unless a source below is marked changed or missing”.
SESSION_HOURS12Within a conversation a quote is sent once, remembered per session id in the temp folder. Forgotten on compaction and on a cleared session (hooks.json runs --forget on PreCompact and SessionStart; a resumed conversation keeps them), and after 12 idle hours.
unknown claimsnew kindWhat a document leaves open is stated, so the model does not go looking: “The 2024 refund policy names no person for the Director role”.
coverage checkat buildWarns about a role nobody holds without an unknown claim, and an entity with no claims. The repo graph has none.
benchmarkfixedbench/live_eval.py gives the graph condition the documents the graph was built from, and reports runs that searched.

Why it still searches

The runs that still searched show two causes.

  • The provenance line named a folder the model could not find. It says the facts come from “9 documents in corpus/”. In the test folder there is no corpus/, and in 5 of the 12 runs that searched with the fix, the first tool call was a Glob for it. In real use the documents are in the folder you work in and the name resolves; the benchmark's fixed setup (Result 3) did not search.
  • The hint is an instruction the injection cannot outweigh. “Our company docs are in this folder” tells the model where the truth is, and in the test folder those really are different files from the graph's sources, so checking them is reasonable. The guidance line did not change that: Sonnet read the folder in every run, before and after.

Next steps

  • Drop the folder name from the provenance line, and say that the quotes were checked against the files just now and do not need opening unless marked. That removes the lookup behind 5 of the 12 remaining searches.
  • Test the hint where it is true: in a folder holding the graph's own sources, where “the docs in this folder” are the documents the quotes come from. The mismatched folder measures a conflict, not normal use.
  • If the hint still wins there, try the standing instruction in CLAUDE.md, which the model reads as project guidance rather than as part of a hook's output.

Tests

78 tests pass (python -m unittest discover tests). New in tests/test_excerpts.py: the build refuses a paraphrased quote, a quote over 300 characters and a quote from a missing document, and accepts markdown and spacing differences; quotes stay within the budget and are never duplicated; the answer comes with its sources; an edited file is marked changed and a deleted one missing; the Director unknown is stated; the coverage check finds a role nobody holds; and the hook sends each quote once per conversation, keeps them on resume and forgets them on compaction.

Still not implemented

  • RAG fallback when no names match (proposal 8): “Who is in charge when the boss is away?” still gets no memory. Waiting on the choice in the proposals doc: keep failing loudly, or add labelled RAG passages.
  • RAG hook speed: it still loads the embedding model on every prompt, about 1.4 s.
  • A standing instruction in CLAUDE.md: the lever left for a prompt that points at the documents (see Next steps).
  • Injection size (the rest of proposal 6): the timing line still opens the injection, and claims plus quotes put it well past the old ~400-token target; this change trades tokens for fewer searches.
  • Merging aliases into names: suggested, not done.
  • Stale pages: docs/improvement-proposals.html, docs/claim-check.html and test-report.md describe earlier versions.

How this was measured

  • Live claude -p runs (Claude Code 2.1.280) on 24 September 2026, claude-sonnet-5 and claude-haiku-4-5-20251001, tools limited to Grep, Read and Glob, user and project settings and MCP servers off, GRAPH_MEMORY_TODAY=2026-09-23. Each prompt ends by asking for a final ANSWER: line, which is graded automatically.
  • Result 1 compares with the claims-only runs of 23–24 September (same questions, folder and grading). Result 2 ran both versions back to back.
  • One run per question: differences of a second or so are within run-to-run noise. The tool-call counts are the firmer evidence. Total cost of these runs: about $1.04.
